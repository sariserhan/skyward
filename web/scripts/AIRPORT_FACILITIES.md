# Airport facility import and static delivery

No paid API, application database, credentials, or production deployment is needed.
Install the **offline importer** dependencies in a Python virtual environment:

```sh
python3 -m venv /tmp/skyward-airports
/tmp/skyward-airports/bin/pip install -r web/scripts/requirements-airports.txt
/tmp/skyward-airports/bin/python web/scripts/import-airport-facilities.py BFS ESB TAS VTE
/tmp/skyward-airports/bin/python web/scripts/import-airport-facilities.py --all
npm --prefix web run build
```

`--all` visits the catalog (currently 1,152 airports), not only a handpicked list.
Progress may span multiple runs when the public service rate-limits or times out.
Codes before `--all` are prioritized. The directory run caches an ICAO-matched
boundary catalog once, then uses nearby boundary searches only for unmatched
airports. Request memory is capped at 128 MB at the source. Defaults: eight airports per batch, requests
at least five seconds apart, one retry, 600 requests and 500 MB downloaded per run.
Use `--delay 30` for slower pacing. Batch sizes from 1 to 32 are supported. Requests are sequential, never concurrent.
HTTP 429 stops immediately; respect Retry-After and resume later. Three consecutive
failed batches also stop. No endpoint rotation to evade quotas. Public Overpass
[usage limits](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)
apply across all work using the same service/account/IP, not just this command.

Each airport is checkpointed in `web/data/facility-import-status.json`. Successful,
empty and review-required v2 imports are skipped on resume. Failed/unattempted
ones are retried. `--refresh BFS` explicitly retries an empty or review-required
airport. `--cached-only` revalidates available v2 snapshots and never requests the network. Ignored raw snapshots live in
`web/data/osm/v2/`; preserve them locally to avoid downloading again. The summary
in `web/data/facility-import-summary.json` describes the last invocation, including
stops, bytes, and outcomes. `facility-import-network-summary.json` preserves the
last network-run result even after an offline revalidation. An unfinished network batch is retried on resume.
Only run one importer at a time; checkpoint files are not a concurrent job queue.

## Matching and validation

1. Search nearby mapped aerodrome boundaries. Prefer matching ICAO, then IATA;
   reject contradictory airport identifiers. A unique untagged boundary containing
   the catalog center is the final boundary match. Very distant/oversized boundaries
   and unsupported antimeridian geometry are rejected for review.
2. When the service has not generated an area for a matched boundary, retry its
   polygon directly. Without a usable boundary, query only explicit aviation facilities in a small
   airport/runway envelope. This is labeled `bounded_aviation_fallback`; surrounding
   generic buildings are never imported through this fallback.
3. Assemble split/reversed multipolygon members, preserve inner rings/courtyards,
   and emit separate outer parts. Omit member ways already represented by a relation.
   Invalid/self-intersecting/open/nonfinite geometry is rejected, not silently repaired.
4. Verify facility containment. Crossing taxi paths are omitted rather than inventing
   a clipped connection. Exact duplicate gates are removed; repeated gate labels at
   different coordinates are retained. Record rejection reasons and disconnected
   path endpoints (a diagnostic, not proof of a complete taxi graph).
5. Keep existing published data on any network/validation failure, empty result, or
   decrease greater than 30% in any existing feature category. Such decreases enter
   `review_required`; inspect the cached source before making a manual publication
   decision. No flag automatically bypasses this protection.

Snapshots include source URL, retrieval time, source hashes, matching method,
boundary OSM ID, ODbL attribution and validation counts. Full query text remains in
the raw local snapshot; the public asset carries hashes. Source timestamps and
counts are not a claim of completeness or current live gate availability. Building
height comes from mapped height/levels where usable, otherwise an illustrative
fallback. All imported facility coverage remains `partial`.

The existing category controls automatically enable when a published airport gains
facilities. Building courtyards are rendered in the globe's flat and terrain views
and the flight simulator. Airport Control's separately generated Godot layouts are
not automatically regenerated by this web-data importer.

## Static/R2 delivery

The app already loads per-airport JSON only for relevant selected/nearby/arrival
views. No global full-detail preload or database writes are introduced.
`npm --prefix web run build` generates `web/public/data/airport-assets.json` with
object keys, SHA-256 hashes, byte sizes, content type and cache policy. The build
rejects any airport above 8 MB or total airport assets above 250 MB. These are
project guardrails, not guarantees about an entire hosting account's free allowance.

Default: serve `web/dist/data/airports/*.json` through the existing static server.
For a later R2 deployment, upload those files preserving `data/airports/` keys,
use `application/json` and `Cache-Control: public, max-age=300`, and compare against
the manifest. Configure a public custom domain and allow GET/HEAD CORS from the
Skyward origin. Set at **build time**:

```env
VITE_AIRPORT_ASSET_BASE_URL=https://YOUR-ASSET-DOMAIN/data/airports
```

This prefix is public, never an R2 API endpoint with credentials. Existing relative
URLs remain the default. Upload, custom-domain configuration and deployment are
intentionally separate; this task does not publish to any account or bucket.

## Checks

```sh
/tmp/skyward-airports/bin/python -m unittest discover -s web/scripts -p test_airport_facilities.py
node --test web/server/airport-buildings.test.mjs
npm --prefix web test
npm --prefix web run build
```

Review `coverage.json`, import outcomes, rejected geometry, and representative
terminal/gate selections before using a new batch. No imported gate is a live
assignment, and disconnected paths must not be treated as verified taxi routes.
